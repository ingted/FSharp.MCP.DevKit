     1 +# Async FSI Tool Calling 發想
     2 +
     3 +## 需求摘要
     4 +
     5 +- 現況 `execute_f_sharp_code` 會同步等待 FSI 執行完成，造成 tool calling 對 agent 是 blocking。
     6 +- 需要新增 `execute_f_sharp_code_async`，收到請求後立刻回 `asyncId`。
     7 +- 原本同步要直接吐回 agent 的執行結果，先放到 `<asyncId, FsiResult option>` cache。
     8 +- 執行順序必須依收到順序 FIFO，不可平行搶占同一個 FSI session。
     9 +- HTTP 需要有 GET endpoint 能檢查某個 `asyncId` 是否已經從 `None` 變成 `Some`.
    10 +
    11 +## 主要想法
    12 +
    13 +1. queue 不放在 pipe client，而放在 `FsiMcpService`。
    14 +   - 原因：`FsiMcpService` 同時位於 MCP tool 與 HTTP route 的共用 service 邊界。
    15 +   - 這樣可直接共用同一份 cache，不需要再跨層同步狀態。
    16 +
    17 +2. queue 使用單一 consumer。
    18 +   - 只要 consumer 永遠一次處理一個 request，就能保證同一個 FSI session 的執行順序。
    19 +   - 比起多個 pipe connection slot，更符合「依序排程」需求。
    20 +
    21 +3. cache 以 `ConcurrentDictionary<string, FsiResult option>` 保存。
    22 +   - enqueue 時先放 `None`。
    23 +   - 執行完成或失敗時改寫成 `Some result`。
    24 +   - HTTP GET 只要檢查是否為 `Some` 即可回報完成狀態。
    25 +
    26 +4. async tool 與同步 tool 並存。
    27 +   - `ExecuteFSharpCode` 保留同步行為，避免破壞現有 client。
    28 +   - `ExecuteFSharpCodeAsync` 提供新路徑。
    29 +
    30 +5. HTTP endpoint 回傳狀態為主，結果摘要為輔。
    31 +   - 最低限度要有 `asyncId`、`exists`、`isCompleted`。
    32 +   - 若已完成，可附帶 `isSuccess`、`output`、`errors`，方便人工除錯。
    33 +
    34 +## 風險
    35 +
    36 +- FSI 本身若執行長時間或卡住，FIFO queue 後續請求也會跟著排隊。
    37 +- 現有 `FsiResult.Value` 與 `FSharpDiagnostic[]` 不適合直接對外 JSON 化，HTTP DTO 需要降維。
    38 +- `examples/ExampleTool/ExampleTool.fsproj` 是壞檔，不能依賴 workspace 級自動分析。

› GET /fsi/async/{asyncId} 這個能變成 MCP TOOL 或者 RESOURCE 之類的??


• 可以。

  比較合適的是 MCP Resource template，其次才是 MCP Tool。

  原因很直接：

  - GET /fsi/async/{asyncId} 是唯讀查詢，沒有副作用。
  - MCP 的語意上，唯讀查詢更像 resource，尤其是你這種「用 id 取狀態」。
  - tool 比較適合會觸發動作的操作，像 execute_f_sharp_code_async 這種 enqueue 行為。

  所以比較乾淨的拆法是：

  - tool: execute_f_sharp_code_async
      - 功能：建立 async job，回 asyncId
  - resource template: fsi/async/{asyncId}
      - 功能：查狀態，回 exists / isCompleted / result

  如果你要從 agent 使用體驗來看，這樣最順：

  1. call tool 取得 asyncId
  2. read resource fsi/async/{asyncId} 輪詢

  當然也能做成 tool，例如：

  - get_async_fsharp_code_status(asyncId: string)

  但這在語意上沒 resource 那麼自然。

  如果你要，我下一步可以直接把現在的 HTTP route 再包一層成 MCP resource template，或同時補一個 status tool。
