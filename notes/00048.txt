      211 +### 4.2 Session Faulted 後的恢復
      212 +
      213 +當執行失敗時，session 會進入 `SessionFaulted` 狀態。後續在同一 session 執行會得到模糊的錯誤訊息：
      214 +> `"Operation could not be completed due to earlier error"`
      215 +
      216 +**恢復方式：**
      217 +1. **建立新 session**（推薦）：`create_fsi_session` 建一個新的
      218 +2. **重置 session**：`reset_fsi_session_routed`（Net10 backend 需注意第 6.3 節的已知 bug）
      219 +
      220 +### 4.3 `#r` 載入 DLL 失敗的常見原因
      221 +
      222 +1. **DLL 已被 host process 載入不同版本** — host process (`/app/*.dll`) 自帶許多 runtime DLL，若你的 DLL 與 host 版本衝突，`#r` 會靜默失敗
      223 +2. **缺少 transitive dependency** — 載入 `A.dll` 成功，但 `B.dll` 依賴 `A.dll` 的不同版本
      224 +3. **NuGet 套件相容性** — 並非所有 NuGet 套件都能在 FSI host 環境中載入
      225 +
      226 +**建議策略：**
      227 +- 先測試用 `printfn "hello"` 確認 session 正常
      228 +- `#r` 用完整路徑而非只用檔名
      229 +- 如果某個 DLL 持續失敗，跳過它，看是否能由其他 DLL 的 transitive dependency 帶入
      230 +- 每個 `#r` 單獨執行，立即確認結果
      231 +
      232 +### 4.4 Timeout 參數
      233 +
      234 +- `timeoutSeconds = 0` 或省略 → 使用預設值 30 秒
      235 +- 大型 NuGet 套件載入或複雜計算建議設 60~120 秒
      236 +- Timeout 是 server 端等待 backend 回應的時間，不是 FSI 執行的 wall clock
      237 +
      238 +### 4.5 `#if INTERACTIVE`
      239 +
      240 +FSI host 預設定義 `INTERACTIVE` symbol。如果你的程式碼使用 `#if INTERACTIVE`，FSI 會執行該分支。

      268 +## 6. 已知限制與陷阱
      269 +
      270 +### 6.1 `create_fsi_host` 需要 caller 知道 container 內部細節
      271 +
      272 +**問題：** 必須手動傳入 `/app/Akka.Proc.Supervisor.dll` 等路徑和完整 Akka address。
      273 +**緩解：** 使用本 Runbook 第 2 節的固定 arguments 模板。
      274 +**根本修復：** 應由 server 自動組裝 arguments（已知缺陷）。
      275 +
      276 +### 6.2 `--systemname` 不能是 `proc-system`
      277 +
      278 +**原因：** procnode 會加入 supervisor 的 Akka Cluster，導致 DData WriteMajority 阻塞。
      279 +**正確值：** `fsi-proc`（或任何非 `proc-system` 的名稱）。
      280 +**後果：** 如果用錯，第二個 host 會 timeout，且即使 kill 掉問題 procnode，DData stuck state 仍殘留，需重啟整個 container。
      281 +
      282 +### 6.3 `reset_fsi_session_routed` 對 Net10 backend 的 bug
      283 +
      284 +**現況：** `Net10HostBackend.buildExecRequest` 中的 `ResetSession` case 回傳 `Error "ResetSession is not implemented for Net10HostBackend yet."`，但 `IFsiEx
          +ecutionBackend.ResetSession` 成員**已經實作**。
      285 +**影響：** 透過 `Execute` 路徑觸發 reset 會被誤攔回報不支援。
      286 +**狀態：** Bug，需修正 `buildExecRequest` 或確保走正確的 method dispatch。
      287 +
      288 +### 6.4 `get_fsi_state_routed` 的 dispatch 路徑
      289 +
      290 +**原因：** `buildExecRequest` 的 `GetState` case 回傳 `Error "GetState is handled via GetSessionState."`
      291 +**影響：** 走 `Execute` 路徑會被誤攔。McpExecutionTools 中的 `GetFsiStateRouted` 已正確呼叫 `backend.GetSessionState()`，所以正常使用 tool 不受影響。
      292 +
      293 +### 6.5 Session Faulted 無自動恢復
      294 +
      295 +**問題：** 一旦 execution 失敗，`ExecutionRouter.RouteAndExecute` 會將 session 標記為 `SessionFaulted`，之後所有操作都可能失敗。
      296 +**緩解：** 建立新 session。
      297 +**根本修復：** 需要自動重試或允許在 Faulted session 上嘗試執行。
      298 +
      299 +### 6.6 錯誤訊息過於模糊
      300 +
      301 +**問題：** 許多錯誤回傳 `"Execution failed"` 或 `"Operation could not be completed due to earlier error"`，不含 RequestId、HostId、SessionId 等上下文。
      302 +**影響：** Agent 無法診斷問題根因。
      303 +**緩解：** 查看 `list_fsi_results` 中的 `RawErrorType` 欄位取得更多資訊。
      304 +
      305 +### 6.7 ResultQuery 未實作
      306 +
      307 +**狀態：** Net10HostBackend 和 InProcBackend 都回傳 `UnsupportedOperationException`。
      308 +**影響：** `query_fsi_results` 和 `compare_fsi_results` 的 `fsharpCode` language 模式可能無法使用。built-in query 應正常。
