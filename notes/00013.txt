  - 之前已經有：

      - tests/BackendSelectorTests.fs

  概念上我在固定的是這條鏈：

  tool/service -> ExecutionRouter -> backend -> result/session registry

  也就是說，先不把重點放在 Akka transport 本身，而是先保證：

  - route 會正確傳遞
  - backend 回傳會被正確標準化
  - session 狀態會回寫
  - result 會被保存
  - async queue 不是只回 id，而是真的接到同一條 execution pipeline

  這樣之後不管 backend 是：

  - InProc
  - NetFxRemote
  - 未來的 .NET 10 remote

  都共用同一個 control plane。

  這輪還沒測的是：

  - 真正跨 process 的 Akka end-to-end
  - ProcSupervisor 啟 host
  - .NET 10 host 的實際 provisioning

  所以目前測的是「架構主幹與契約正不正」，不是整套 deployment/e2e。
