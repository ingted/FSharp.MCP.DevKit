• 對，差別就在這裡：

  - dotnet fsi some.fsx
      - 走的是 script/file mode
      - 整個檔案會被當成腳本處理
      - 檔案裡有多個 ;; 通常只是多餘 separator，不會讓後半段消失
  - EvalInteraction(code)
      - 走的是 interactive submission mode
      - 它的語意比較像「把這一段字串當成一次 FSI 主控台輸入」
      - 在這個模式下，;; 是 submission terminator

  所以怪的不是「FSI 本身」，而是：

  - 你把本來偏 .fsx file 語意的一大段 source
  - 直接塞進一次 EvalInteraction
  - 而那段 source 裡又混了 ;;
  - 那它就不再是「腳本檔案」語意，而是「一串互動式輸入」語意

  也就是說，這不是說 FSI source code 有 bug，而是：

  - EvalScriptNonThrowing(filePath) 和
  - EvalInteractionNonThrowing(code)

  本來就是兩條不同 API，語意不同。
  FCS 文件自己也把它們分成兩類，這也是為什麼會同時存在這兩個 API。

  我現在能很硬地證明這件事，不是空猜：

  最小重現：

  open System;;

  - 用 EvalInteraction(code)：

  - .fsx 裡多個 ;; 沒問題
  - 但把含 ;; 的整段 .fsx source 直接當成一次 EvalInteraction 的 input，就有問題
  - 這也是為什麼我們需要先切 chunk，再逐段 EvalInteraction
