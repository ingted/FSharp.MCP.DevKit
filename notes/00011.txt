• 大方向沒問題，但有一個地方要切清楚，不然實作會自撞。

  actor per session 我認為是正解。
  result_op 由 parent 處理也合理，但 parent 不應直接在 actor thread 內做重 query；比較好的做法是：

  1. parent 收 result_op
  2. 驗證 agentId/hostId/resultIds
  3. 從 ResultRegistry materialize records
  4. 把計算丟給 ResultQueryService
  5. parent 回覆結果

  這樣 session actors 只專注 execution/state，不背結果集運算。

  真正有問題的是第 1 點如果你是字面上的「所有 host 都必須經 ProcSupervisor」：

  - net10 host：完全合理，應強制經 ProcSupervisor
  - netfx host：也合理，應強制經 ProcSupervisor
  - inproc host：這不是實體 process，字面上不能真的經 ProcSupervisor

  所以這裡我建議收斂成下面這句，設計上最乾淨：

  - 所有 out-of-proc host 建立流程一律強制經 ProcSupervisor
  - inproc 不視為正式 host provisioning 目標，只保留給 backward compatibility 的 default route

  也就是說新世界裡：

  - create_fsi_host 只支援 netfx / net10
  - inproc 不讓使用者顯式建立
  - 舊工具若沒指定 route，才落到 legacy inproc default-host

  這樣沒有矛盾，而且更符合你要把它從 toy 拉到 production-ready 的方向。
