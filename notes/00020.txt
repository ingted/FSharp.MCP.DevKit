  - 目前 image 對「server-only + in-proc default host + 多 session」是夠的，我剛剛驗到的功能也都能跑。
  - 但對「create_fsi_host 建不同 host」這件事，缺的核心不是 publish/copy 某個 DLL，而是 server 啟動時根本沒有把 ProcSupervisor / FsiSupervisor client wiring 起來。

  1. 在 server startup 注入 IProcSupervisorClient 與 IFsiSupervisorClient
  2. 提供可連到的 ProcSupervisor / FsiSupervisor endpoint 與 config

  目前程式邏輯是：

  - InProcBackend 永遠會註冊
  - FSI_ENABLE_REMOTE_CLIENT=true 只是在此之外，再多註冊一條 NetFxRemote backend
  - default route 仍然是 default-agent/default-host/default-session，而 default-host 是 in-proc

  對應程式在：

  - src/FSharp.MCP.DevKit.Server/Program.fs
  - src/FSharp.MCP.DevKit.Server/McpFsiTools.fs

  所以結論是：

  - true: in-proc 仍可用，外加啟用 legacy remote client
  - false: 只剩 in-proc，不啟用 legacy remote client

  真正的風險不是「in-proc 不能用」，而是：

  - 但只要 server 有正常起來，in-proc session 本身不會因此失效

• 根因我確認了，不是 ProcSupervisor package 壞掉，而是啟動方式不對。

  你現在的 image 只有：

  - /app/Akka.Proc.Supervisor.dll
  - /app/FSharp.MCP.DevKit.runtimeconfig.json
  - /app/FSharp.MCP.DevKit.deps.json

  但沒有：

  - /app/Akka.Proc.Supervisor.runtimeconfig.json

  所以直接跑：

  dotnet /app/Akka.Proc.Supervisor.dll

  會被當成「獨立 app」，然後就報你看到的：

  - 缺 libhostpolicy.so
  - 找不到 Akka.Proc.Supervisor.runtimeconfig.json

  我已經把修正改在：

  - /workspace/home/mcp/docker/FSharp.MCP.DevKit/entrypoint.sh

  現在改成：

  dotnet exec \
    --runtimeconfig /app/FSharp.MCP.DevKit.runtimeconfig.json \
    --depsfile /app/FSharp.MCP.DevKit.deps.json \
    /app/Akka.Proc.Supervisor.dll ...

  這樣 Akka.Proc.Supervisor.dll 會直接吃 fsharp-devkit 這份已 publish 出來的 runtime graph，不需要它自己再有一份 .runtimeconfig.json。

  你現在要做的就是：

  1. 用新的 /workspace/home/mcp/docker/FSharp.MCP.DevKit/entrypoint.sh 重建 image
  2. 重新部署 container

  這次不需要改 NuGet package，也不需要改 FSharp.MCP.DevKit repo 程式碼。只要重 build docker image 就行。
