• 不是 Akka.NET 標準機制，這是這個專案自己加的初始化。

  先講你問的第一句：

  - 我現在重新測到的結果是：protobuf.ensure 其實有 done
  - 之前看起來像卡在那裡，是因為我當時的診斷不夠細，後來又被我自己加壞的 ReceiveAny 干擾
  - 我剛剛重跑本地 procnode 真實遠端測試，log 已經明確看到：
      - step=protobuf.ensure
      - step=protobuf.ensure.done
      - step=serialization.dump
      - step=serialization.dump.done
      - step=create.fsifs
      - step=create.fsifs.done
      - step=install.pcsl
      - step=install.pcsl.done
  - 所以現在本地這條線不是卡在 ProtoBufInit.ensureUnitSerializer()

  你問的第二句，tryRegisterUnitIntoModel model 是什麼：

  - 這裡的 model 不是 actor model，也不是 domain model
  - 它是 protobuf-net 的 RuntimeTypeModel
  - 也就是 protobuf-net 在 runtime 用來記錄「哪些 .NET 型別怎麼做 protobuf 序列化」的型別模型

  對應程式在：

  - /workspace/home/work/PulseTrade.fs/Libs/Akka.FSI.Supervisor/Supervisor.fs

  這段核心做的事情是：

  - 找 ProtoBuf.FSharp.Serialiser
  - 用反射找 registerRuntimeTypeIntoModel
  - 把 typeof<unit> 註冊進某個 RuntimeTypeModel

  所以 tryRegisterUnitIntoModel model 的白話是：

  - 嘗試把 F# unit 註冊到 protobuf-net 的 runtime type model 裡

  你問第三句，FsiSupervisorActor 為什麼要做 ProtoBufInit.ensureUnitSerializer()：

  原因不是 Akka.NET，而是它這個 FSI supervisor 內部還整合了 PCSL / protobuf 這套儲存層。

  這個 actor 啟動時會做兩件跟 PCSL 有關的事：

  1. 建 PcslFileSystemActor
  2. 呼叫 PcslFileSystem.install ...

  而 PCSL 這套在這個 repo 裡是透過 protobuf-net 做資料模型序列化的。
  F# 裡某些資料結構如果碰到 unit，protobuf-net 預設不一定認得，所以這裡先做：

  - default model
  - protobuf-fsharp 的 model
  - PCSL 自己的 model
  - loaded models 掃描

  目的就是：

  - 避免之後 PCSL / protobuf 在真正存取資料時，才因為 unit 型別沒註冊而炸掉

  所以一句話總結：

  - ProtoBufInit.ensureUnitSerializer() 不是 Akka 的需求
  - 是 這個專案把 Akka.FSI.Supervisor 跟 PersistedConcurrentSortedList + protobuf-net-fsharp 綁在一起後，多出來的初始化需求
